# AGENTS.md — правила проекта «Меню на неделю»

## Главное
- **Перед любыми изменениями сверяйся с [docs/SPEC.md](docs/SPEC.md)** — это источник истины по требованиям. Если задача расходится со спецификацией, сначала уточни, затем обнови SPEC.md.
- **Все тексты UI — на русском.** Кнопки, подписи, сообщения об ошибках, плейсхолдеры, title/aria-label, manifest. Код, идентификаторы и комментарии — на английском.
- **Mobile-first.** Основное устройство — телефон. Сначала верстаем под ширину ~375px, крупные зоны нажатия (≥44px), учитываем safe-area (нижнее меню).
- **Офлайн.** Никаких сетевых запросов за данными: сервера и авторизации нет, всё хранится в IndexedDB на устройстве. Внешние CDN не подключаем.
- **Бизнес-логику покрывай тестами** (Vitest): автосортировка, сборка недели, правила повторов, перенос, список покупок, экспорт/импорт. Чистые функции — в `src/logic/`, без зависимостей от React и Dexie, чтобы их было легко тестировать.

## Стек
React 19 + TypeScript (strict) + Vite 6, Tailwind CSS v4 (`@tailwindcss/vite`), Dexie 4 (IndexedDB) + `dexie-react-hooks`, `vite-plugin-pwa`, Vitest (+ `fake-indexeddb` для тестов БД).

## Структура
```
docs/SPEC.md          техзадание
src/
  main.tsx, App.tsx   вход и корневой компонент
  types.ts            доменные типы и константы-справочники (разделы, слоты, статусы)
  db/                 Dexie: схема (db.ts), начальные данные (seed.ts)
  logic/              чистая бизнес-логика + *.test.ts рядом
  components/         переиспользуемые UI-компоненты (BottomNav и т.п.)
  screens/            экраны верхнего уровня (Неделя, Блюда, Покупки, Морозилка, Ещё)
```

## Соглашения
- Схему Dexie меняем только через новую `db.version(n+1)` с миграцией; старые версии не редактируем после выпуска.
- Даты храним как ISO-строки (`YYYY-MM-DD` для дней, полный ISO для меток времени).
- Удаление блюд — через флаг `archived`, а не физически.
- Команды: `npm run dev`, `npm run build`, `npm test`, `npm run lint` (проверка типов tsc).
